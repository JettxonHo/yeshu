## 为什么不得再次执行

原脚本是一次性工具,存在破坏性缺陷,因此已删除而不是"修成幂等":

1. **不幂等**:字段创建类 mutation 重复执行会创建**重名字段**,污染项目视图与数据;
2. **整体替换语义**:字段更新类 mutation 会用传入的 options 数组**整体替换**现有选项——必须携带全部现有 option 的 id 才不会清空已有 item 的字段值。脚本写死了当时的 id,对任何后续 schema 变更都是地雷;
3. **写死资源标识**:脚本硬编码了项目与字段节点 ID,环境漂移后误执行可能作用于错误对象;
4. **无 dry-run、无差异确认、无备份、无回滚方案**。

对当前生产项目重跑,或仿写一份直接执行,可能**破坏字段结构与已有任务的字段值**。

上述信息只存在于本地 `.env` 与 GitHub / 阿里云控制台,不进仓库。

## 未来字段变更的强制流程

任何 GitHub Projects V2 字段结构变更,必须:

1. **独立迁移 PR**:与业务代码变更分离,PR 描述即迁移方案;
2. **先读当前 Schema**:变更前查询并记录当前字段与选项(名称级,不含节点 ID);
3. **dry-run**:先以只读查询验证目标与预期差异;
4. **明确差异**:在 PR 中逐项列出"变更前 → 变更后";
5. **人工批准**:不得由 agent 自行执行 mutation;
6. **回滚方案**:包含备份(导出当前字段结构)与明确回滚步骤;
7. **禁止无备份的整体替换**:不允许在未备份、未验证的情况下用 options 数组整体替换现有选项。
